QuickMUD Class Notes
====================

This file documents the current QuickMUD / ROM 2.4b6 class system. It replaces
older Merc-era assumptions that no longer match this source tree. For a deeper
combat-focused analysis, see:

    docs/class-combat-notes.md


Current Classes
---------------

The player class count is controlled by MAX_CLASS in src/merc.h. The current
value is 4.

The four current player classes are defined in class_table in src/const.c:

    mage     prime INT  first weapon dagger  THAC0 20 ->  6  HP  6-8   mana yes
    cleric   prime WIS  first weapon mace    THAC0 20 ->  2  HP  7-10  mana yes
    thief    prime DEX  first weapon dagger  THAC0 20 -> -4  HP  8-13  mana no
    warrior  prime STR  first weapon sword   THAC0 20 -> -10 HP 11-15  mana no

All four classes currently have skill_adept set to 75, so the maximum practiced
skill percentage is not presently class-specific.


class_table
-----------

The central organizing table for PC classes is class_table, an array of struct
class_type. The structure is defined in src/merc.h and the data is defined in
src/const.c.

The fields of class_table are:

    char *name;

        The full player-facing class name.

    char who_name[4];

        The three-letter class abbreviation used in who listings and other
        compact displays.

    sh_int attr_prime;

        The class's prime stat. At first login, a new level-0 character gets
        +3 to this stat. Prime stats also receive higher effective and trainable
        caps through get_curr_stat() and get_max_train().

        Older documentation claimed prime stats were cheaper to train. That is
        not true in this tree: do_train() initializes cost to 1 and does not
        raise the cost for non-prime stats.

    sh_int weapon;

        The legacy/intended first weapon object vnum. Current new-character
        outfitting is more indirect: do_outfit() chooses a school weapon from
        the character's highest known weapon skill.

    sh_int guild[MAX_GUILD];

        Guild room vnums. act_move.c blocks characters from entering guild
        rooms belonging to other classes.

    sh_int skill_adept;

        The maximum percentage a PC of this class can reach by practicing a
        skill or spell. Currently all classes use 75.

    sh_int thac0_00;
    sh_int thac0_32;

        The class's melee accuracy curve. one_hit() interpolates between these
        values by level, then compresses very good negative THAC0 values. These
        values are one of the main direct ways class affects combat.

    sh_int hp_min;
    sh_int hp_max;

        The class's hit point gain range on level-up, before constitution and
        other advancement modifiers. hp_max also affects passive hit point
        regeneration for PCs.

    bool fMana;

        Whether the class is treated as a full mana/spell class. This affects
        mana gain, spell save odds, and spell cast level. Non-mana classes can
        still know spells if tables grant them, but they cast at three-quarters
        level in do_cast().

    char *base_group;
    char *default_group;

        Skill groups granted during creation. base_group is always added with
        rom basics. default_group is added when the player skips customization
        and is also used for older player-file skill initialization.


Other Class-Specific Tables
---------------------------

pc_race_table in src/const.c:

    Each PC race has class_mult[MAX_CLASS]. This changes experience per level
    for each race/class pair.

skill_table in src/const.c:

    Each skill and spell has skill_level[MAX_CLASS] and rating[MAX_CLASS].

    skill_level controls when each class may use the skill or spell. In this
    source tree, unavailable mortal skills are usually set to level 53, not the
    older Merc value 37.

    rating controls availability and learning cost. A rating below 1 means the
    class cannot buy/gain that skill normally. Positive ratings affect creation
    point cost, train cost through gain, practice speed, and natural improvement
    chance.

group_table in src/const.c:

    Each skill/spell group has rating[MAX_CLASS]. Group ratings control whether
    a class can select or gain the group and how many creation/train points it
    costs.

title_table in src/const.c:

    Titles are indexed by class, level, and sex. Adding or removing a class
    requires keeping this table in sync.

pose_table in src/act_comm.c:

    Pose messages are indexed by level and by class. Each pose entry contains
    two messages per class: one for the actor and one for the room.


Class Effects On Combat
-----------------------

Class affects combat through several layers:

    Direct combat math:
        class_table supplies PC THAC0 endpoints used by one_hit().

    Growth:
        class_table supplies prime stat, HP gain, mana behavior, and practice
        cap. Prime stats feed combat through STR hitroll/damroll, DEX armor
        class and combat-command formulas, CON hit points/regeneration, WIS
        practices, and INT learning.

    Access:
        skill_table and group_table determine which combat skills, weapon
        skills, defenses, and spells a class gets, when they are available, and
        how quickly or cheaply they improve.

    Defaults:
        base_group and default_group shape the starting build before the player
        has made many choices.

Examples from the current tables:

    Warriors have the best THAC0, best HP gain, early parry, shield block,
    bash, enhanced damage, rescue, second attack, and third attack.

    Thieves have the second-best THAC0, early backstab, dodge, trip, second
    attack, and stealth/utility skills.

    Clerics are full mana classes with medium THAC0/HP, shield block, healing,
    support magic, and some combat spells/skills.

    Mages are full mana classes with the weakest THAC0 and HP gain, but broad
    spell access.


NPC Class-Like Behavior
-----------------------

NPCs do not use PC class_table as their main class system.

Builders give mobs class-like behavior with act flags such as cleric, mage,
thief, and warrior, plus offensive flags such as bash, berserk, disarm, dodge,
fast, kick, parry, and trip.

New-format mobs receive stat adjustments from ACT_WARRIOR, ACT_THIEF,
ACT_CLERIC, and ACT_MAGE in db.c. one_hit() also uses these act flags to choose
NPC THAC0 endpoints. NPC skill percentages come from get_skill() formulas based
on level and flags, not from PC learned skill arrays.

This matters for class redesign: changing player classes will not automatically
change mob behavior unless the mob flag model, OLC, and builder docs are also
updated.


Adding Or Changing A Class
--------------------------

Class changes are table-wide changes. Before editing, decide whether existing
player files must migrate. Early QuickMUD planning currently allows player files
to be wiped later, which makes larger class changes easier than a live migration.

Checklist for adding a new class:

1. Increment MAX_CLASS in src/merc.h.

2. Add a class_table entry in src/const.c.

3. Add one class value to every pc_race_table class_mult array.

4. Add one class value to every skill_table skill_level array.

5. Add one class value to every skill_table rating array.

6. Add one class value to every group_table rating array.

7. Add a full title_table block for the new class.

8. Add two pose_table messages per pose level for the new class.

9. Decide base_group and default_group membership, including weapon basics and
   any default combat package.

10. Update creation, help, player-facing docs, builder docs, and any tests or
    scripts that assume four classes.

11. Audit NPC builder behavior separately. PC classes and NPC act/offensive
    flags are related concepts, but they are not the same data path.


Known Current Stale References
------------------------------

Some inherited Merc/ROM docs may still describe older behavior. In this source
tree:

    - Unavailable mortal skills are usually represented with level 53, not 37.
    - Prime stats are not cheaper to train in do_train().
    - Starting equipment follows known weapon skill in do_outfit(), not only
      class_table.weapon.
    - Mobs are better understood through act/offensive flags than through PC
      class_table.
